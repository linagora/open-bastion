# SBOMs Generation

The third-party tool [Syft](https://github.com/anchore/syft) is used
to generate SBOMs for `open-bastion` DEB packages. Those SBOMs catch
all packages required by the DEB packages.

Make sure `syft`, `jq` and `docker` are installed, then:

``` sh
$ PACKAGE_PATH=./build/open-bastion_0.6.2_amd64.deb
$ OUTPUT_DIR=./build
$ ./docker-sbom/generate-sbom.sh ${PACKAGE_PATH} ${OUTPUT_DIR}
```

The Docker image `debian:trixie-slim` is used to collect dependencies
recursively; Use the `--base-image` command line parameter to specify
a different image.

## Methodology

Note that Syft doesn't support generation of SBOM for a single DEB
package. Closest supported features are the generation of SBOM for
full package databases and Docker images.

We choosed to run Syft on a slim Debian Docker image after an
installation of the DEB package. CycloneDX nodes for each package are
collected from the generated SBOM. The final SBOM for the DEB package
only is generated by hand, with the dependency graph read from the dpkg
database of that image (`dpkg-query`): each dependency is resolved to
what is installed, the first alternative satisfied by an installed
package, virtual packages being resolved through the `Provides` of
their installed providers. Packages unreachable from the installed
package are left out, and the necessary CycloneDX nodes are inserted
into the hand-made SBOM to fullfill all internal references.

Only `Depends` and `Pre-Depends` are followed, and version constraints
are not compared: the image is built by installing the package, so dpkg
already holds a version satisfying each of them.

## Validation

``` sh
$ SBOM=./build/open-bastion_0.6.3_amd64.deb-debian_trixie-slim-cyclonedx.json
$ docker run \
	-v ${SBOM}:/src/cyclonedx.json \
	cyclonedx/cyclonedx-cli validate \
	--input-file /src/cyclonedx.json
```

## Uses

One can use [grype](https://github.com/anchore/grype) to collect CVEs:

``` sh
$ SBOM=./build/open-bastion_0.6.3_amd64.deb-debian_trixie-slim-cyclonedx.json
$ grype sbom:${SBOM}
```
