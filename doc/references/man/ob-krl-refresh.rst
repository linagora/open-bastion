ob-krl-refresh
==============

Synopsis
--------

::

   ob-krl-refresh [-c file] [-o file]

Description
-----------

``ob-krl-refresh`` downloads the SSH key revocation list (KRL) published by
the LemonLDAP::NG portal at ``<portal_url>/ssh/revoked``, checks it, and
replaces the file named by the ``RevokedKeys`` directive of
:manpage:`sshd_config(5)`. It is run by ``ob-krl-refresh.timer`` on hosts
configured for maximum security (``ob-bastion-setup --max-security``),
every 30 minutes by default.

:manpage:`sshd(8)` treats a revocation list it cannot parse as revoking every
key, so the file is only replaced by one that is known to be good:

1. The list is downloaded to a temporary file in the same directory as the
   target, never to the target itself.

2. It must start with the KRL magic and format version 1. When
   :manpage:`ssh-keygen(1)` is installed, the whole list must also parse
   (``ssh-keygen -Q``).

3. It is then renamed over the target, mode 0644. The rename is atomic: sshd
   reads either the previous list or the new one, never part of either.

When the download or a check fails, the current list is left untouched and the
program exits non-zero, so the service is reported as failed. An identical
list is not rewritten, but its modification time is updated: the age of the
file says when the list was last confirmed, so a check such as
``"find /etc/ssh/revoked_keys -mmin +60"`` keeps telling a working refresh
from a broken one.

Options
-------

.. option:: -c, --config file

   Configuration file (default ``/etc/open-bastion/openbastion.conf``).

.. option:: -o, --output file

   Revocation list to replace (default ``/etc/ssh/revoked_keys``).

.. option:: -h, --help

   Show usage and exit.

.. option:: -V, --version

   Show version and exit.

Configuration
-------------

These keys are read from the configuration file at every run, so a change to
it takes effect at the next refresh:

``portal_url``
   Portal URL (required). ``portal`` is accepted as a fallback.

``verify_ssl``
   ``false``, ``0``, ``no`` or ``off`` disables TLS certificate verification.

``ca_cert``
   CA certificate used to verify the portal.

``timeout``
   Connection timeout in seconds (default 10). The whole transfer is bounded
   to six times this value.

The configuration file must be owned by the user running the program and must
not be group- or world-writable; otherwise the program refuses to run.

Schedule
--------

The timer runs the refresh at minutes 0 and 30 of every hour
(``OnCalendar=*:0/30``), catches up after downtime (``Persistent=true``), and
adds up to one minute of random delay to spread a fleet's requests.
``ob-bastion-setup --krl-refresh-interval`` *N* writes the drop-in
``/etc/systemd/system/ob-krl-refresh.timer.d/schedule.conf`` that changes it
to every *N* minutes. To change it by hand:

::

   systemctl edit ob-krl-refresh.timer

   [Timer]
   OnCalendar=
   OnCalendar=*:0/10

Check the timer and the last run with:

::

   systemctl list-timers ob-krl-refresh.timer
   journalctl -u ob-krl-refresh.service

Exit status
-----------

``0``
   The list is current: replaced, or already identical.

``1``
   Configuration error.

``2``
   The portal could not be reached or refused the request.

``3``
   The portal did not return a valid KRL.

``4``
   The new list could not be installed.

Files
-----

``/etc/open-bastion/openbastion.conf``
   Configuration file.

``/etc/ssh/revoked_keys``
   Revocation list read by sshd.

``/etc/systemd/system/ob-krl-refresh.timer.d/schedule.conf``
   Schedule drop-in written by the setup for a non-default interval.

History
-------

Before 0.7.0 the refresh was a script generated by the setup into
``/usr/local/bin/open-bastion-refresh-krl``, run from
``/etc/cron.d/open-bastion-krl``. :doc:`ob-post-upgrade(8) <ob-post-upgrade>`
and a new run of the setup replace that job with this timer, keeping its
interval.
